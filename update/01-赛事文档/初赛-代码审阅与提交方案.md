### 1.4 结果验证 — 项目最强项，PPT 必须放大

这块是真功夫，且是评委在别家作品里见不到的：

- **pass^k**（`src/engine/evaluation/passK.ts`）：同一样本重复 k 次裁判，k 次全维达标才算通过。设计依据在注释里写得很扎实（引 Farquhar Nature 630:625 语义熵、τ-bench pass^1≈0.6/pass^8≈0.25）。`mode:'repeat'|'sessions'` 两种语义显式区分，防止字段名被误读。
- **评委偏差审计**（`judgeClient.ts` `auditJudgeBias`）：逐维极差 → maxSpread > 1.5 判 unstable → 置信度 ×0.8 + 追加「建议人工复核」证据。
- **Krippendorff α**（`judgeEnsemble.ts`）：k 次重复当 k 个评委副本算一致性，α<0.67 再降 ×0.9。注释里明确写了矩阵朝向（行=维度、列=运行）搞反会让稳定 agent 算出负 α——说明作者真的踩过并修过。
- **抗偏差 prompt**（`buildJudgeRubricPreamble`）：位置偏差用 `rubricVariant` 旋转维度顺序；冗长偏差、自我增强偏差、锚定偏差各有一条显式指令；0/5 双端锚点（Prometheus 式 rubric）。
- **三态来源标注**：`source: 'judge'|'mixed'|'degraded'`，且 `degraded` 的评估**不允许沉淀经验规则**（`handlers.ts:285`，注释叫「垃圾进垃圾出防线」）。

> **这是全场差异化最高的一段。别人的多 Agent 都在讲「我能跑通」，只有你在讲「我怎么知道跑出来的结论可信」。PPT 应当给它一整页，标题就叫「不是让 Agent 跑起来，是让结论可被审计」。**

## 第 3 部分 · 作品简介草稿（500 字以内）

> 项目名称（20 字内）：**AgentCorp：企业 Agent 准入与协同治理基座**（18 字）

**正文（468 字）：**

**问题与场景**：企业引入 Agent 时无法回答三个问题——该选哪个、能不能上线、上线后是否劣化。选型靠 star 数与体感，准入无基线，上线后无回归，出事无证据。这是所有行业引入 Agent 的共性关卡。

**核心方案**：把「Agent 准入与治理」建成多 Agent 闭环。准入工单进入后，Dispatcher（编排主控）按岗位类型动态拆解，Recruiter（能力基线测试）产出结构化证据，Evaluator（评估中心）以 LLM-as-judge 打六维分并做可靠性审计，Boss（治理决策）拍板准入/观察/下线/回滚，高风险动作需人工确认，决策结果沉淀为结构化规则回注下一轮。全流程八步闭环，每步带 Agent + Skill 双标签，落盘为可回放 JSONL。

**创新点**：不止让 Agent 跑通，更让结论可被审计。pass^k 重复采样（k 次全维达标才算通过）、评委偏差审计（逐维极差超阈即降置信并转人工）、Krippendorff α 一致性、维度顺序旋转抗位置偏差、抗冗长/自我增强偏差 rubric，以及 judge/mixed/degraded 三态来源标注——降级评估禁止沉淀经验，杜绝垃圾进垃圾出。

**开放/复用价值**：MIT 开源。Skill 注册表为可逆插件内核（可注册/可注销/可 patch/Provider 可替换）；已接入 MCP 客户端运行时（stdio/SSE/HTTP 三传输）；Trace 已按 OpenTelemetry GenAI 语义约定投影，可直连任意兼容后端；裁判后端可替换，避免评测被单一模型家族绑定。评估层可独立复用于任何 LLM-as-judge 场景。

**当前进展**：4 张异构 Agent 角色卡与 5 个 Skill 已实现并注册；闭环 Demo 可离线跑通并导出 Trace；前端 633 项、模型服务 271 项单测全绿，双 tsconfig 类型检查零错误，CI 全门禁通过。
