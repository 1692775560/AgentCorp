背景摘要

Background

一个开源 Agent 在 5 个月里拿下 36 万 Star，成为 GitHub 史上获星最多的软件项目。而真正上手养过它的人里，三分之一最后没留下来[4]。

这个反差就是我们要做的生意。需求是真的——中国已有 73% 的职场人每周都在用 AI，其中 26% 几乎每天用，显著高于全球平均[1]；留下来的重度用户里，41% 每月为此实付超过 200 元[4]。但留存是差的，因为没人能回答一个最朴素的问题：这几十个长得一模一样的 Agent，哪个适合我手上的活？

现有的答案只有两种，都不管用。厂商跑分测的是模型通用能力，不是你的工作流；网上帖子是别人用别人的任务跑出来的。而 Agent 的能力恰恰高度依赖具体任务——同一模型在大学学历水平任务上成功率约 66%，任务越长成功率越低，约 2 小时的任务已降到 50% 上下[7][17]。所以今天大家找 Agent 的第一渠道已经变成同事朋友推荐（44.6%），而不是逛商店[4]：口碑正在替代榜单，因为榜单失效了。

AgentCorp 是一个中立的第三方，帮你把候选 Agent 放到你自己的真实任务上考一遍，看谁真能干、谁只是看起来能。考完留下合拍的，组成你自己的 AI 团队，像带员工一样带他们。任务数据留在你的电脑上，我们不碰。

还有一件我们更在意的事。身边越来越多人反馈：Agent 用久了，深度思考的能力在退化——它替你写完了，你也就不再自己想了。所以我们不做拐杖。考核的过程会让你逐渐看清：什么该外包、什么必须自己长、你的不可替代性在哪。这是一个「职场教育 +」的工具，目标是让人借 Agent 变强，而不是被 Agent 取代思考。

◆核心差异化：两张榜单

所有做评测的都在争一件事——谁的客观跑分更权威。我们是唯一一个承认「好」本身是主观的。

榜单谁来打分回答什么问题
客观榜标准考场 + 可复现的机器评分：任务完成度、返工次数、耗时、token 成本「谁真的能干活」
主观榜你自己排序：审美、沟通风格、价值观、你愿意为完成度牺牲多少速度「谁跟我合得来」
同一批 Agent，看重性价比的人和看重交付速度的人，应该看到两张不同的榜。把「合不合你」交回给你，是产品设计，也是我们的立场。

这也是巨头结构上难以复制的地方：模型厂商必须宣称自己客观、权威、第一。它们不能承认排名因人而异——那等于承认自己的跑分不重要。而我们从第一天起就是这么设计的。

机器负责能被验证的部分（完成度、返工、耗时、成本），你负责只有你能判断的部分（顺不顺眼、对不对味）。你的偏好会被记下来，喂回下一次匹配——用得越久，配得越准。

◆不做拐杖：让人变强，而不是替人思考

Agent是嵌进你工作流里升级产出的，不是来替你开车的。我们相信好的 Agent 应该「教人上树摘果子，而不是替人上树、让人守株待兔」。

这不只是价值观，它决定了产品的具体形态。用户在派任务前必须自己写清验收标准（DoD）——这是完成度评分的依据，同时也是一次思维训练：把模糊的想法拆成可验收的条目，这件事 Agent 替不了，而它恰恰是职场核心能力。复盘时用户要判断哪里不对、怎么改，这是给反馈的能力。久而久之，能力账本会告诉你：什么该外包、什么必须自己长、你的不可替代性在哪。

别人卖「替代你的 AI 员工」，我们卖「让你更值钱的一套方法」。前者的天花板是你的工资，后者的天花板是你的成长。

这也是留存的来源：工具可以被替换，但用户在这里积累的能力账本和偏好模型是他自己的资产，搬不走。

为什么盯「职场生态」而不是「数字员工」？「数字员工」那层已经挤满了巨头和创业公司（Artisan / 11x / Genspark [12]），而我们也不认为「替代真实员工」是可持续的方向。我们选的这一层——评测、推荐、撮合，帮人做选择——2025 年整体规模只有 0.5 亿元[6]。

我们不用这个数字的增速来说服你，基数太小，任何外推都不可靠。我们想说的是另一件事：这一层小到今天没人愿意认真做——巨头做不了（它们必须证明自己第一，不能做中立裁判），卖 Agent 的做不了（利益冲突）。这个空位不是因为没价值，是因为只有中立第三方才站得住。而它必然要有人填：40% 的企业应用将在 2026 年底内置任务型 Agent[10]，供给越多，「该选谁」就越贵。

◆为什么是现在：三个结构性原因

① 供给爆炸，而且每一家都自称最强。Genspark 以「雇佣 AI 员工而非购买工具」切入，11 个月达成 2 亿美元年化收入，估值约 16 亿美元[12]；全球 Agent 公司从 300 家膨胀到 1000 家以上[11]。这些公司的成功恰恰是我们存在的理由——卖家越多、宣传越响，「谁来替我判断」就越刚需。卖铲子的人赚钱的时候，验矿的人才有生意。

② 「管 Agent」正在变成一门正经职能。业界已在形成共识：要给 AI Agent 分配数字身份、运行沙箱与治理策略，像管理员工一样管理它们[16]。同时爱分析观察到，企业投入正从 IT 信息化预算迁向与业务绑定的 HR / 外包预算，数字员工从「降本工具」变成「独立对结果负责」的角色[6]。这与我们的 HR 隐喻同构——个人先用起来，企业再跟上。

③ 用户的问题变了。从「能不能用」（2023–24）到「好不好用」（2025），再到今天的「该选谁、怎么分工、怎么考核」（2026）。最直接的证据是找 Agent 的第一渠道已经变成熟人推荐（44.6%）而非官方商店[4]：用户已经在自发寻找可信的第三方意见，只是今天只能靠同事。

市场窗口、预算迁移与心智成熟三重因素在此交汇，构成了「为什么是现在」的完整回答。

◆为什么定这个价

重度用户每月已在 Agent 上实付超过 200 元[4]，而其中相当一部分花在最后被卸掉的工具上。¥59–99 的定位不是「工具订阅费」，是省下试错成本的钱：一次选错的代价既包括订阅费，也包括返工的工时。我们刻意不做 ¥19.9——低价会把产品锚定成小工具，而我们卖的是决策依据。

口径也要说清：用户付的是管理与决策费，不是 token 费。我们不靠卖推理赚钱，这是中立性的经济基础——如果我们从推理量抽成，就有动机推荐更贵的 Agent。

◆单位经济学与毛利保护

评测吃算力，但我们的架构天生省成本：本地桌面端 + 自带模型 Key——推理的钱用户自己出；国内模型（DeepSeek / 通义千问 / Kimi）已主导个人 Agent 用户[4]，BYOK 零门槛 → 边际成本接近 0。

同一个架构还解决了最大的采用障碍。「用真实工作任务做考核」听起来很好，但用户第一反应必然是「我凭什么把公司资料交给你」。本地优先让这个问题不成立：任务内容与产出留在你的电脑上，平台只接收匿名化的匹配信号。企业版同理——数据不出内网是 HR 采购的硬门槛，我们从架构上就满足，而云端评测的竞品必须重做。

◆冷启动策略

标准考场（平台自建拟真任务）+ 自带 Agent 让「没交易也有人用」；用户带着真实任务来 → 任务数据训练匹配 → 越匹配越留人 → 卖家跟着需求进场。「海选」从开放市场进货，「入职评估 + 绩效中心」在本地就能自己转起来 [P1]。

增长策略（GTM）

Go-To-Market

「用得越多、配得越准」——每一次真实任务的绩效考核，都是最好的匹配学习信号。

◆怎么拿到前 1 万个用户

① 让考核结果变成社交货币。产品名字就是「You are fired」——普通人第一次有机会当老板、给 AI 打绩效、开掉不合格的。六维雷达图、我的 AI 团队战绩卡、开除记录，都是天然可分享的内容。这是内容驱动获客，不是投广告：每一份分享出去的雷达图都在替我们解释产品是什么。

② 从「已经在用、但正在流失」的人群切入。OpenClaw / Claude Code / 各类 Agent 的中文社区里，聚集着大量装了卸、卸了装的用户——他们已经付费、已经有痛感，不需要被教育。这是最低成本的第一批种子用户。

③ 榜单本身是内容资产。「同工种 Agent 客观榜」有持续的搜索与讨论价值，是可复用的自然流量入口，也是卖家愿意主动上架的理由。

④ 个人 → 小微团队的自然扩散。用户在自己的工作里跑顺了，会带进团队；团队用起来，就是 L3 企业版的入口。先 C 后 B，不做冷启动的企业销售。

北极星指标：每周完成考核的真实任务数。它同时代表使用深度、数据积累与留存质量——注册数会骗人，真实任务不会。

◆我们还需要验证什么（诚实披露）

今天我们有的是自身与身边职场人的一手观察：Agent 越装越多、像快消品一样分不清哪个适合自己；以及一个更让我们在意的反馈——用久了之后深度思考的能力在退化。这是我们做这件事的起点，但还不足以称为验证。

本轮我们要在结营前完成 30 场结构化用户访谈，验证三件事：

  • 流失是否真由「选不对」造成——你装过几个、卸了几个、为什么卸？（若主因是能力不足而非匹配不当，我们的前提就不成立）
  • 人们是否愿意为「决策依据」付费——你上次选错 Agent 损失了多少时间？愿意花多少钱避免它？
  • 能力退化是否被普遍感知——用了 AI 之后，你觉得自己哪方面变强了、哪方面变弱了？

我们把这三个问题写进 BP，是因为它们中任何一个的答案为「否」，都会改变产品方向。与其假设，不如去问。

◆为什么是我们

这个产品的核心问题，本质上不是工程问题，是「如何测量人与 Agent 的能力和匹配」的问题——六维能力雷达要成立，就必须回答：这个分数测到的是什么？换个考题还成立吗？两次打分为什么不一致？这些在心理测量学里都有成熟的方法论（构念效度、评分者间信度、共同方法偏差）。

行业里几乎所有做 Agent 评测的团队都由工程主导，他们的解法通常是不断增加维度、换更强的模型。而这是一个测量学问题，不是算力问题。

成员背景在这个产品里负责什么
创始人Emory 本科 → 宾夕法尼亚大学教育学院硕士；长期研究方向为人的心理健康与全面发展评测方法论与量表设计、主观偏好建模、能力账本的教育学设计、产品哲学定调
联合创始人北京交通大学计算机技术硕士在读；多次黑客松获奖评测引擎、Agent 运行时、模型服务
联合创始人武汉纺织大学电子信息工程本科；多次黑客松获奖桌面端与全栈实现、设计系统

做这件事的初心，来自一手观察。身边朋友的吐槽很一致：Agent 一个个装上来，本以为是在增强自己，结果像快消品一样分不清哪个适合自己。但更让创始人警觉的是另一件事——Agent 似乎在削弱人深度思考的能力。一个研究人的发展的人，看到这个变化很难不在意。

所以 AgentCorp 不做拐杖。我们先解决用户最急的问题（选对、用好），再往上走一层：让用户在这个过程里真正长出竞争力。一个关于「AI 如何影响人的能力发展」的产品，由研究人的发展的人来做——我们认为这是正确的配置。

风险与对策

Risks
模型巨头下场 高

全家桶 + 自家评测。对策：中立第三方是结构性屏障（运动员 ≠ 裁判）；绑定跨生态协议（A2A/ANP）而非单一厂商。

谁来监督裁判 高

我们用大模型打分，凭什么可信？对策三层：① 客观真值锚定——完成度、返工数、耗时、成本来自可验证的运行记录，不由模型主观判断；② 可复现——固定考题集、固定评分尺度（rubric）与随机种子，同一 Agent 重复测量差异可公开；③ 公开 rubric + 人工抽检——评分标准与打分依据全部留痕可查。我们不要求用户信任我们的模型，只要求他们能验证我们的过程。

刷分与作弊 高

榜单一旦有价值，卖家就会针对榜单优化——这是所有榜单的宿命。对策：① 考题集分为公开集与保留集，排名以保留集为准并定期轮换；② 最终排名以用户真实任务表现为权重主体，公开考场只作准入筛选；③ 异常检测（同工种表现分布突变、仅在公开题上高分）。真实任务数据无法被提前针对，这是我们相对纯榜单产品的结构优势。

推荐失误的责任边界 中

作为中立第三方，推荐错了谁负责？对策：定位为决策辅助而非结果担保——提供证据、留痕与置信度，不做效果承诺；服务条款明确责任边界；高风险工种（财务、法务、医疗相关）默认强制人工复核，不提供全自动建议。

冷启动 中

无交易无网络效应。对策：BYOK + 标准考场让「没交易也有价值」；先 C 后 B。

数据隐私 中

任务/绩效数据敏感。对策：本地优先架构，数据默认不出本机；企业版私有化部署。

消费产品留存难 高

消费级 AI 产品留存普遍偏低。对策：能力账本 + 绩效数据持续增值；以「任务」而非「聊天」为高频触发器。

技能退化伦理 中

评测是否会加剧依赖？对策：产品在立场上就解毒——人在回路、主观赋权、可拖拽。「任务可以外包，判断力不行」[M]。
