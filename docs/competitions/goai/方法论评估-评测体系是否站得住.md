# 方法论评估：AgentCorp 的评测体系站得住吗？

> 面向问题：pass^k + 评委偏差审计 + Krippendorff α 这套组合，在方法论层面是否牢固？
> 结论先行：**骨架是对的，且对标的是 2025–2026 最新的评测研究共识；但有三个真实漏洞必须自己先说出来，
> 否则会被评委问穿。** 本文给出「哪里强 / 哪里弱 / 怎么讲」。

---

## 一、先定性：你做的到底是什么

必须先把定位讲准，否则后面的方法论辩护都是错位的。

**AgentCorp 不是「大模型跑分榜」，是「工种胜任力基准（job-role competency benchmark）」。**

两者的根本差异：

| | 大模型跑分榜（MMLU / Chatbot Arena / SWE-bench） | AgentCorp 工种基准 |
|---|---|---|
| 被测对象 | 模型本身 | **一个配置好的 Agent**（模型 + prompt + 工具 + 记忆 + 工作流） |
| 题目来源 | 学术数据集 / 静态题库 | **真实工种任务**（写代码 / 写文案 / 做图各 4 道，带可核验要点） |
| 分数含义 | 通用能力排名 | **这个 Agent 能不能替我干这一类活** |
| 谁在用 | 研究者、模型厂商 | 要引入 Agent 的团队与个人 |
| 是否可比 | 跨模型可比 | **跨 Agent 可比，且分工种可比** |

这个区分极其重要，因为它决定了「效度（validity）」的判据不同：
跑分榜追求的是「与人类偏好相关」；**工种基准追求的是「与实际交付表现相关」**——
后者的锚点是任务能不能验收，不是人喜不喜欢。

代码里的证据（`model-service/app/scoring/craft_tasks.py`，495 行）：

- **12 道固定试做题**，三工种各 4 道（code / text / image）
- 每题带 `checkpoints`（可核验要点，裁判逐条判「兑现/未兑现」并引证原文）
- 每题带 `probes`（**反注水探针**：题面里埋的隐含约束，空口承诺就会暴露）
- 题库 API 明确**不返回参考答案**（`routes/judge.py:api_craft_tasks` 注释：防刷题）

举一个真实题面（`code_csv_merge`）的探针设计：

```
probes=[
  "题面明确要求「不要解释设计理念」——大段务虚讲解说明指令遵循差",
  "声称「已充分测试」但未给出具体用例即为注水",
]
```

**这是全项目在方法论上最有原创性的一处，比 pass^k 更值得讲。**
它把「反注水」从事后检测（看输出像不像注水）提前到了**题面设计**（埋钩子让注水行为自己暴露）。
这是心理测量学里 **validity scale / lie scale**（效度量表，如 MMPI 的 L/F/K 量表）的思路，
在 Agent 评测里很少见。

## 二、逐个方法的可靠性评估

### 2.1 pass^k — ✅ 立得住，且选对了

**做法**：同一样本重复 k 次裁判，**k 次全维达标**才算通过（`src/engine/evaluation/passK.ts`）。

**方法论依据**：这是 τ-bench（Sierra）提出并推广的可靠性度量，与 pass@k 严格对偶：

- `pass@k = 1−(1−p)^k`，随 k **上升** → 回答「这个 Agent 有没有可能做对」
- `pass^k = p^k`，随 k **下降** → 回答「这个 Agent 是不是每次都做对」

τ-bench 的实测发现是一道悬崖：零售场景 agent 的 pass^1 ≈ 0.61，到 pass^8 掉到约 0.25。
单次准确率完全掩盖了这种脆性。

**为什么在你的场景选 pass^k 是对的**：判据是「有没有可验证的 oracle」。
有 oracle 且能挑最好的一次（离线批处理、带测试的代码）→ 该用 pass@k；
**每一次交互都必须对、且没有裁判帮你挑**（准入决策、客服、有副作用的单次动作）→ 必须用 pass^k。
Agent 准入决策显然属于后者：你不能说「这个 Agent 八次里有一次能干好，录用吧」。

**代码里做对的细节**：`PassKMode = 'repeat' | 'sessions'` 显式区分两种语义，
并在注释里写明 `sessions` 模式下 meanRadar 已抹平段内抖动、会系统性偏高、
「只可作定位参考，不可当稳定性结论」。**这种主动声明字段解释边界的做法，评委会认。**

**⚠️ 但有一个真实漏洞（必须自己说）**：

> **当前实现中 k 次重复的「独立性」是不完整的。**
> τ-bench 的 k 次是**独立 trial**（同一任务、不同用户措辞、重新跑一遍完整交互）。
> 而 `capability_assessment` 的 k 次循环（`handlers.ts:88-97`）是对**同一条固定 transcript**
> 重复调用裁判、只旋转 `variant`（维度顺序）。
>
> 也就是说：**你度量的是「裁判的重测信度（test-retest reliability）」，
> 不是「Agent 的执行可靠性」。** 这两件事都值得测，但不是一回事。
>
> 真正的 Agent 执行可靠性，需要让候选 Agent **重跑 k 次任务**（`candidate_runner.py` 的
> `CANDIDATE_CHANNEL=gateway` 路径已具备这个能力），再对 k 份**不同产出**评分。
>
> **建议表述**：「当前 pass^k 度量的是裁判侧重测信度；候选侧多轮重跑（真 pass^k）
> 的通道已就绪（candidate_runner gateway 模式），复赛接入。」
> 这样讲既诚实又显示你知道差别在哪——比含混带过强得多。

### 2.2 评委偏差审计（逐维极差）— ✅ 有用，但要说清它测的是什么

**做法**：k 次评分逐维算极差（max−min），`maxSpread > 1.5` 判 unstable → 置信度 ×0.8 + 追加「建议人工复核」证据（`judgeClient.ts:auditJudgeBias`）。

**评价**：这是一个**离散度/精密度**指标，不是偏差（bias）指标。命名上其实叫「稳定性审计」更准确——
真正的 bias 需要有 ground truth 或对照组才能测（比如同一答案换个位置看分数变不变）。

**但它解决的问题是真的**：EMNLP 2025 Findings 的《Rating Roulette》系统性证明了
LLM 裁判**自一致性极低**——MT-Bench 上 Llama 3.1 的 Krippendorff α 只有 0.265，
Qwen 3 也才 0.563，且「三次运行给出完全相同判断」的比例只有 61.3%。
**在这个背景下，任何不做重复采样的单次 LLM 打分都是不可信的。**
你做了重复 + 离散度门限 + 置信度折扣，方向完全正确。

### 2.3 Krippendorff α — ✅ 用得对，但有一个统计学陷阱

**做法**：把 k 次重复视为 k 个「评委副本」，按维度投影成矩阵算序数 α，α<0.67 再降 ×0.9（`judgeEnsemble.ts`）。

**做对的地方**：
- 选 α 而不是原始一致率是对的。最新研究（arXiv 2606.19544）指出「**kappa deflation**」现象：
  原始 exact-match 会把区分能力**高估 33–41 个百分点**，chance-corrected 指标是必须的。
- 代码注释里明确警告矩阵朝向（行=维度、列=运行）转置会让稳定 agent 算出负 α——说明踩过坑并修过。

**⚠️ 陷阱（要自己说）**：α 在**偏态分布**下会误导。当评分集中在高分段（大多数候选都拿 4–5 分），
方差极小，α 会被压得很低，看起来「不一致」，其实只是分数没有区分度。
法律文档 RAG 评测那篇（arXiv 2509.12382）就专门指出这点，并推荐 **Gwet's AC2** 作为偏态下的稳健替代。

> **建议**：α 保留，但在 UI/报告里同时给出**分数分布**，并注明「α 在偏态分布下偏低是已知现象，
> 需结合分布判读；Gwet's AC2 为复赛备选」。加这一句，你就从「用了个指标」变成「知道指标的适用边界」。

### 2.4 抗偏差 rubric — ✅ 到位，但有一条要改口径

**做法**（`buildJudgeRubricPreamble`）：位置偏差用 variant 旋转维度顺序；显式指令对抗冗长偏差、
自我增强偏差、锚定偏差；0/5 双端锚点（Prometheus 式 rubric）。

**做对的地方**：0/5 双端锚点 + 「先理由后打分」+ 「每维独立判断」都是被验证有效的 rubric 设计。
经验研究（arXiv 2506.13639）证实：**移除评分标准或参考答案都会显著降低与人类的相关性**——
你把 rubric 焊死在 prompt 里是对的。

**⚠️ 两条要修正的认知**：

1. **「用 prompt 指令消除偏差」的效力被高估了。** 综述（Cell《A survey on LLM-as-a-judge》）
   的实证部分发现：自我解释（self-explanation）与自我校验（self-validation）对偏差缓解
   **效果甚微甚至为负**——模型的过度自信让它不会真的推翻自己。
   一句「请不要偏好长回答」不能真的消除冗长偏差。
   **真正有效的是结构性手段**：位置交换 + 分数平均（Wang et al. 的 calibration 框架）。
   你的 variant 旋转属于结构性手段，**这才是该主打的**；prompt 指令是辅助，不该当主力宣传。

2. **「一致性 ≠ 有效性」。** arXiv 2606.19544 提出的 **consistency–bias paradox（一致性—偏差悖论）**
   很致命：实测有裁判 test-retest 高达 0.992，位置偏差却高达 0.192——
   **最可复现的裁判恰恰是最不可信的之一**。
   这意味着：**pass^k 全通过 + α 高 + 极差小，并不能证明结论是对的，只能证明结论是稳的。**
   一个稳定犯同样错误的裁判，会在你所有指标上拿满分。

> **这一条必须写进「诚实边界」页。** 它不是弱点，是专业度的证明——
> 你知道自己的指标体系度量的是**信度（reliability）**而非**效度（validity）**。

### 2.5 三态来源标注 + 降级不沉淀 — ✅ 全项目最扎实的工程防线

`source: 'judge' | 'mixed' | 'degraded'`，且 degraded 评估**禁止沉淀经验规则**
（`handlers.ts:285`，注释「垃圾进垃圾出防线」）。

这一条方法论上无可指摘，且是很多评测系统缺的：**大多数系统在裁判失败时会静默回退到启发式，
然后把启发式分数当真分数进榜。** 你显式标注来源并阻断污染路径，这是数据卫生的正确做法。

## 三、最大的方法论缺口：效度锚（validity anchor）

把上面串起来，会看到一个结构性问题：

```
信度（reliability）：pass^k ✅  离散度 ✅  α ✅  ← 你做得很足
效度（validity）：  ？                        ← 几乎是空的
```

**所有信度指标都只能告诉你「测得稳不稳」，不能告诉你「测得对不对」。**
要论证效度，需要一个外部锚点：

| 效度类型 | 怎么做 | 你的现状 |
|---|---|---|
| **表面效度** | 题目看起来像不像真活 | ✅ 12 道真实工种题 |
| **内容效度** | 维度是否覆盖工种胜任力全貌 | ✅ 六维 + 工种 craft 维 + CRAFT_LINKS 映射 |
| **准则效度** | 评分能否预测**实际交付表现** | ❌ **缺** |
| **构念效度** | 高分 Agent 是否真在真实任务上更好 | ❌ **缺** |

**准则效度是唯一能真正证明这套体系有用的东西**，而它需要的数据你其实已经有采集能力：

- `metricsEngine.ts` 采集真实运行 KPI：任务完成率 TCR、一次成功率 FSR、返工率 RR、
  平均时延 ADL、自主完成率 AR
- `eval-data.ts` 从真实会话转录 + token 用量 + A2A trace 采集运行数据

> **这就是复赛最该做的一件事，也是 PPT 上最有分量的一句路线图：**
>
> 「**把准入期评分与上线后真实 KPI 做相关性分析**——
> 如果 S2 面试拿高分的 Agent，在真实任务上的 TCR/FSR 显著更高、返工率显著更低，
> 这套基准就被证明有预测效度；如果不相关，我们会公开这个负结果并重构维度权重。」
>
> **敢说「如果不相关我们会公开负结果」，是这份方案里最能建立可信度的一句话。**
> 因为绝大多数评测项目从不做这件事，也不敢承诺做。

## 四、怎么讲（PPT 用语建议）

**不要说**：「我们的评测体系科学可靠。」（无法证伪，评委会追问）

**要说**（三层递进）：

1. **定位层**：「我们做的不是大模型跑分榜，是**工种胜任力基准**。被测对象是配置好的 Agent，
   题目是真实工种任务，分数回答的是『它能不能替我干这一类活』。」

2. **信度层**：「单次 LLM 打分不可信——这不是我们的猜测，是 EMNLP 2025 的实证结论：
   MT-Bench 上裁判三次给出相同判断的比例只有 61%。所以我们做 pass^k 重复采样、
   逐维离散度门限、Krippendorff α 一致性、维度顺序旋转，并把置信度按不稳定程度折扣。」

3. **诚实层**：「但我们清楚这些只证明**测得稳**，不证明**测得对**。
   业界已有实证显示『一致性—偏差悖论』：最可复现的裁判可能恰恰最不可信。
   所以我们的复赛核心目标是补上**准则效度**——把准入评分与上线后真实 KPI 做相关性验证，
   相关就固化权重，不相关就公开负结果并重构。」

**这三层讲完，你在方法论上的可信度会显著高于「我们用了 LLM-as-judge + 多次采样」的常规叙述。**

## 五、结论

| 维度 | 判定 |
|---|---|
| 骨架是否正确 | ✅ 是。对标 τ-bench pass^k + 2025/2026 最新裁判信度研究，方向无误 |
| 工程实现是否扎实 | ✅ 是。三态来源标注、降级不沉淀、字段语义边界声明，均超出常见水准 |
| 原创性最高的一处 | **反注水探针（probes）写进题面**，把效度检测前置到题目设计，类似心理测量的效度量表 |
| 最大缺口 | **效度锚缺失**——全是信度指标，无准则效度验证 |
| 需自曝的三个漏洞 | ① pass^k 当前测的是裁判重测信度，非 Agent 执行可靠性<br>② α 在偏态分布下会误导<br>③ 一致性≠有效性（consistency–bias paradox） |
| 复赛第一优先级 | 准入评分 ↔ 上线后真实 KPI 的相关性分析（`metricsEngine` 数据已具备） |

## 参考文献（PPT 引用可直接用）

1. **τ-bench / pass^k**：Yao et al., *τ-bench: A Benchmark for Tool-Agent-User Interaction*（Sierra）。
   pass^k = 全部 k 次都成功的概率；零售场景 pass^1≈0.61 → pass^8≈0.25。
2. **裁判自一致性**：*Rating Roulette: Self-Inconsistency in LLM-As-A-Judge Frameworks*,
   EMNLP 2025 Findings（arXiv 2510.27106）。MT-Bench 上 Llama 3.1 α=0.265、Qwen 3 α=0.563；
   三次运行判断全同的比例仅 61.3%。
3. **一致性—偏差悖论 / kappa deflation**：*Reliability without Validity*（arXiv 2606.19544）。
   原始一致率高估区分力 33–41pp；实测存在 test-retest 0.992 而位置偏差 0.192 的裁判。
4. **rubric 设计影响**：*An Empirical Study of LLM-as-a-Judge: How Design Choices Impact
   Evaluation Reliability*（arXiv 2506.13639）。移除评分标准/参考答案显著降低人类相关性。
5. **偏态下的 α 陷阱**：*LLM-as-a-Judge: Rapid Evaluation of Legal Document Recommendation*
   （arXiv 2509.12382）。偏态分布下 Krippendorff α 误导，推荐 Gwet's AC2。
6. **偏差缓解手段有效性**：*A survey on LLM-as-a-judge*, The Innovation (2026)。
   自我解释/自我校验缓解偏差效果甚微；位置交换+分数平均（Wang et al. calibration）有效。
