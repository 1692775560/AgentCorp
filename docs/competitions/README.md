# 赛事材料目录（competitions/）

> **本目录存放「面向特定赛事的提交材料」，与产品本体解耦。**

## 为什么要有这个目录

AgentCorp 会参加多场赛事（阿里 GOAI、华为昇腾等）。如果把某一场赛事的定位、
指定模型、指定硬件写进 README 和核心代码注释里，会造成两个问题：

1. **观感问题**：A 赛事的评委在仓库里看到 B 赛事的定位声明，观感极差。
2. **架构污染**：为迎合某场赛事的「指定模型/指定芯片」而在核心代码里写死依赖，
   会让项目失去可移植性——而可移植性本身就是这个项目的技术主张之一。

因此我们采取的规则是：

> **产品本体（README / src / electron / model-service）保持赛事中立；
> 任何赛事专属的定位、话术、提交物，一律收敛到 `docs/competitions/<赛事>/` 下。**

## 目录约定

```
docs/competitions/
├── README.md              # 本文件：规则说明
├── goai/                  # 阿里云 GOAI 大赛（Agent Infra 新智基座赛道）
│   ├── 初赛-代码审阅与提交方案.md
│   ├── rerun-package.md        # 代码包清单与一键运行步骤
│   └── verification-report.md  # 自动化验证报告（pnpm verify:goai 生成）
└── _archive-ascend/       # 华为昇腾挑战赛（历史材料，已归档）
    └── prd-ascend-2025.md
```

## 赛事中立性检查清单（每次提交前过一遍）

产品本体中**不应出现**下列内容：

- [ ] 特定赛事名称作为项目定位（「本项目是 XX 大赛参赛作品」）
- [ ] 「指定模型」「统一环境」等赛事约束被写成架构前提
- [ ] 单一厂商硬件/芯片被写成默认必需项（应为「可选后端之一」）
- [ ] 只对某一赛事评委有意义的表述（「评委机」「统一环境复现」等）

可以出现、且应当出现的是**技术中立的等价表述**：

| ❌ 赛事绑定表述 | ✅ 中立等价表述 |
|---|---|
| 「本项目为 XX 挑战赛作品」 | （删除；赛事定位放 competitions/ 下） |
| 「指定模型 MiniCPM-o 4.5」 | 「默认全模态裁判，后端可替换（JudgeBackend 协议）」 |
| 「昇腾 NPU 统一环境」 | 「支持 cuda / cpu / 异构加速卡，自动降级」 |
| 「评委机零配置复现」 | 「离线可复现（Mock 模式 + 确定性种子）」 |

## 这条规则本身就是技术主张

裁判后端不绑定单一模型家族，不只是为了参赛方便——用模型评模型存在
**自我增强偏差**（裁判偏爱与自己同家族的产出）。可替换后端是缓解该偏差的
架构级手段，写在 `model-service/app/judge_backend.py` 的三实现（http / local / mock）里。

换句话说：**赛事中立 = 技术正确**，两者在这个项目上是同一件事。
